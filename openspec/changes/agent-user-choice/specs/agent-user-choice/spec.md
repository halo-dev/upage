## ADDED Requirements

### Requirement: Agent can request user choice during execution
The system SHALL allow the Agent to call a `requestUserChoice` tool at any point during its execution to present multiple options to the user and pause until the user responds.

#### Scenario: Agent initiates a choice request
- **WHEN** the Agent determines that user input is needed for a decision (e.g., layout style, color scheme, component selection)
- **THEN** the Agent SHALL call the `requestUserChoice` tool with a question, a list of options, and the selection mode

#### Scenario: Choice request is streamed to the client
- **WHEN** the Agent calls `requestUserChoice`
- **THEN** the system SHALL stream a `data-user-choice` part to the client containing the choice request metadata
- **AND** the system SHALL write the choice request into the assistant message's metadata as `choiceData.request`

### Requirement: Agent receives user choice result in message context
The system SHALL ensure that after the user makes a selection, the choice result is available to the Agent as part of the message history when the Agent resumes execution.

#### Scenario: Agent reads previous choice result
- **WHEN** the Agent resumes execution after a user choice
- **THEN** the Agent SHALL be able to access the user's selection from the preceding user message's metadata
- **AND** the system prompt SHALL include instructions reminding the Agent to respect the user's choice

### Requirement: Agent limits choice requests per turn
The system SHALL prevent the Agent from initiating multiple choice requests in a single tool call batch or in rapid succession.

#### Scenario: Agent attempts second choice in same turn
- **WHEN** the Agent has already called `requestUserChoice` in the current turn
- **THEN** the tool execute function SHALL return an error indicating only one choice request is allowed per turn

### Requirement: Choice options are generated by the Agent
The system SHALL allow the Agent to generate diverse, meaningful options for the user to choose from, based on the current task context.

#### Scenario: Agent generates layout options
- **WHEN** the user asks for a landing page and the Agent needs to decide on layout
- **THEN** the Agent SHALL generate 2-5 distinct layout options (e.g., "hero + features grid", "split-screen with CTA", "video background with overlay")
- **AND** each option SHALL have a clear, human-readable label and a brief description

### Requirement: Choice request supports multiple selection modes
The system SHALL support `single` (N pick 1), `multiple` (N pick many), and `hybrid` (predefined options plus free text input) selection modes.

#### Scenario: Single choice mode
- **WHEN** the Agent calls `requestUserChoice` with `mode: 'single'`
- **THEN** the client SHALL render radio buttons allowing exactly one selection

#### Scenario: Multiple choice mode
- **WHEN** the Agent calls `requestUserChoice` with `mode: 'multiple'`
- **THEN** the client SHALL render checkboxes allowing zero or more selections

#### Scenario: Hybrid mode with custom input
- **WHEN** the Agent calls `requestUserChoice` with `allowCustomInput: true`
- **THEN** the client SHALL render an additional text input field alongside the predefined options
- **AND** the user SHALL be able to submit either selected options, custom input, or both
